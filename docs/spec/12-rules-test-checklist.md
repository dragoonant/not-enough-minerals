# 12 Rules test checklist

One line = one testable rule: `ID: rule -> expected outcome. (source)`. Engine tests are named by ID, e.g.
`it('ATK-050 Surge moves dice only on a tag match')`. Source keys and citation format are in `10` section 1
(R p.N = PDF page marker). Precedence: CL/CT > card text > F > R > QS. "(RULING)" marks a line that tests a
logged decision in `docs/needs-rules-check.md` instead of printed text; re-check it when a new source lands.
Every bracketed tag in specs 10-19 appears here; extra fine-grained IDs (HIT, SRG, ARM, EVD, SHD, CR, PASS,
OBJ, REA, TRN, COST) split a coarse spec tag into separately testable rules.
